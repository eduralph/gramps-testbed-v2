# Brief — issue 13163 / german-date-bis-parsed-as-month

> The Plan artifact (docs 02 §PLAN). Human-authored. Do reads ONLY this file.

- **Slug:** german-date-bis-parsed-as-month
- **Defect:** With the German UI, entering "bis 1760" ("until 1760") as a date was
  silently converted to "0.8.1760" (August 1760): the parser matched "bis" via the old
  German month name "bisemond" (= August). The bug's headline summary is broader —
  "Gramps silently overrides the user's 'Text only' date configuration" — because typing
  parseable text while Type = "Text only" flips the date back to a Regular parsed date.
- **Success criterion:** Parsing the German text "bis 1760" no longer yields an August
  date; it parses as a "to/until 1760" date (modifier MOD_TO, year 1760). The reported
  "0.8.1760" August conversion no longer occurs. Demonstrable by C4-verify against a
  German date-parser test.
- **Invariant to restore:** n/a — non-structural behavioural bug fix (principles.md §1.1).
- **Repo + branch target:** gramps-project/gramps @ maintenance/gramps61
- **Surfaces:** data — the verified symptom is in the German date parser; the residual
  "Text only" override lives in the GUI date editor (see out of scope).
- **Difficulty:** low (for the verified parser symptom).
- **Scope:** confirm the reported "bis 1760 → August" symptom is gone — German "bis" now
  parses as the MOD_TO modifier, added to `_date_de.py`'s modifier table. / out of scope,
  both flagged for the human as still-open and design-sensitive: (1) the headline
  cross-locale behaviour that the date editor (gramps/gui/editors/editdate.py) silently
  re-parses text and overrides an explicit "Text only" type — unresolved UX design;
  (2) the German parser's loose abbreviation month keys auto-generated by its prefix
  tables ("e" = September, "ern" = August, "ho" = July, …), which the reporter objects to
  — a deep cross-locale change to month-name matching, not this verify's reported symptom.
- **Repro instruction:** `DateParserDE().parse("bis 1760")` — pre-(historic) parsed as
  month 8 (August); on the current target it parses as MOD_TO with year 1760. (GUI:
  create an event, set the date to "bis 1760", and observe it is no longer turned into
  August 1760.)
- **Test file:** gramps/gen/datehandler/test/date_de_test.py (new) — assert
  `DateParserDE().parse("bis 1760")` has modifier MOD_TO and year 1760 (month 0), not
  month 8. NOTE: this verifies current behaviour with no patch to revert, so `run-verify`
  emits `PDCA-UNVERIFIABLE` → §6 NEEDS-HUMAN (expected for verify-first); the test ships
  and must pass.
- **Citations expected:** Do must cite path:line on maintenance/gramps61.
- **New/removed files:** adds gramps/gen/datehandler/test/date_de_test.py (no translatable
  strings) → po/POTFILES.skip. (datehandler/test/ already exists.)
- **Prior-art check (triage cycles):** searched gramps/gen/datehandler/_date_de.py history
